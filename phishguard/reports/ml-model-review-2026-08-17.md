## 1. Overview of the Model Engine
*   **Model Type**: CatBoost Classifier (`CatBoostClassifier`).
*   **Input Features**: 14 URL lexical/security indicators (e.g., length, subdomain count, punycode/unicode checks, confusion characters, TLD checks).
*   **Training Configuration**:
    *   Iterations: 1000
    *   Learning Rate: 0.05
    *   Depth: 8
    *   Eval Metric: AUC
    *   Class Weights: Balanced (auto adjustment)
    *   Early Stopping: 50 rounds

---

## 2. Training Data Sources
*   **Phishing URLs**: Sourced from PhishTank verified database (and supplemented with OpenPhish feeds).
*   **Legitimate URLs**: Sourced from Tranco Top 1M list (standard daily download).
*   **Ratio**: Balanced 50/50 dataset generated by `backend/ml/data/download_data.py`.

---

## 3. Reproducibility Test Findings
To verify reproducibility, a verification tool `backend/ml/verify_reproducibility.py` was created. It runs two training loops (`Model A` and `Model B`) with identical parameters and seeds on a fixed sample dataset (1000 records).

*   **Prediction Probabilities Difference**: `0.000000000000` (bit-identical).
*   **Feature Importances Difference**: `0.000000000000` (bit-identical).
*   **Conclusion**: Model training is completely deterministic and reproducible when fixed random seeds are declared.

The verification report was generated and cached under `backend/ml/models/reproducibility_report.json`.

## 4. Remote Storage Integration (Self-Healing Registry)
To support production scaling and prevent dependency on local filesystem artifacts, we built an external object storage interface under `backend/registry/storage.py` and integrated it into the registry.

### Features:
1.  **S3/Object Storage Integration**: Toggled by setting environment variables (`MODEL_STORAGE_PROVIDER='s3'`, `AWS_BUCKET_NAME='...'`). If configured, uploads artifacts directly via `boto3`.
2.  **Simulated/Mock Cloud Fallback**: If boto3 is missing or S3 configurations are absent, it copies artifacts to a local simulated remote cloud bucket under `scratch/simulated_cloud_bucket/`.
3.  **Self-Healing Recovery**: If a registered model's local directory or binary artifact is deleted or lost, retrieving the artifact via the registry automatically fetches the backup file from remote/simulated storage and restores it.

This self-healing flow was tested and verified under `backend/tests/test_registry.py` (`test_self_healing_from_storage`).

## 5. Recommendations for Production
1.  **Real-Time Data Pipelines**: Periodically fetch new feeds and trigger retraining using AWS SageMaker, GCP Vertex AI, or isolated Celery workers rather than direct local execution.
2.  **MLflow Registry**: Transition the filesystem-backed registry to a centralized hosted MLflow server for full tracking of parameters, runs, and artifacts.
3.  **Real-time Feature Drift Detection**: Hook up validation checks on incoming URLs to monitor features (e.g., shift in average URL lengths or TLD frequencies) and trigger warnings if distribution shifts.
